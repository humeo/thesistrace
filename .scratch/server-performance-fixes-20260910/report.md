# 服务器性能与内存修复

日期：2026-09-10。修复基线：`ad16ea9bd8e369c20270d187499cb089b7b7069e`。性能修复：`8af1b76`；取消验收同步：`1f6ead9`；取消协议修复：`420af5f`。

## 已实现

- 财务投影读取保持 Arrow 列式去重，避免整表转 Python 字符串、字典再转回 Arrow。保留严格小写 SHA-256 校验、首次键顺序及末条记录覆盖语义。
- Strategy Sweep 的策略执行与共享 Artifact 恢复不再重新加载 Alpha 字段和行业数据；保留不可变计算绑定、跨窗口持仓及执行价格上下文。
- Data Operator 在成功或失败的完整操作结束后执行 GC、Arrow 内存池释放及系统分配器内存归还。与 Batch 使用同一内存释放函数；空轮询不触发回收。
- Factor Batch 上报实测的输入、Alpha、Factor 和最终汇总耗时；共享标签准备只计入第一项，窗口消息反映该窗口工作，最终消息反映该项累计工作。
- Research 子进程在中间块／最终块等待确认时正确处理合法取消命令，以退出码 0 结束，不再把取消误判为非法确认（退出码 65）。

此前约 2.16 GiB 的空闲 Data Operator 内存中，约 1.64 GiB 经只读主堆遍历确认已经释放给 glibc，但尚未归还操作系统。本次修复的是操作结束后的内存归还边界；不将此前未逐对象检查的其他映射宣称为绝无泄漏。

相邻研究窗口仍需读取 PIT 期初财务状态。本次没有引入跨窗口缓存，也没有删去历史事实；有边界的增量复用保留为后续优化空间。

完整性能检查发现了已有取消采样竞态：在 `child_started` 事件后立即取消，子进程尚未就绪时可能走受支持的强制终止路径。该样本在 1.544 s 内进入 cancelled，未产生 Result，checkpoint 和 pin 均为 0；失败字段是要求协作退出的 `child_exit_code`。本次保持退出码、清理及 5 s 取消限额，改为测试 Worker 在目标 Run 首块确认前等待父进程放行；父进程提交取消后释放屏障，不能提前进入下一块读取。同步屏障仅存在于验收工具，生产代码的协议修复见下文。

同步修复验证：事件匹配回归先 2 fail / 3 pass，修复后相关 29 项单元测试及运行器测试通过；公开 `cancel-worker` 命令的放行和 EOF 失败两项管道回归通过。运行器测试首次因沙箱不能绑定回环端口失败，使用已授权本地端口权限后通过。Spec 补审发现日志轮询仍有竞态，加入同步屏障后两路复审均 0 项。补跑使用全新测试项目，保留原始失败报告，以 SHA-256 记录复用的 20 轮样本及来源镜像。

首次屏障补验又稳定暴露协议缺陷：两个 Research Kind 均在首块边界收到合法 cancel 后退出 65，而不是协作退出 0。监听线程已接受 cancel，等待 ACK 的主循环却漏掉此分支。新增真实子进程回归，在中间块和最终块等待时发送 cancel，两例先失败，补上精确 cancel 分支后通过；其他 ACK 校验不变。该两行修复经两路审查，各 0 项发现。最终真实依赖补验通过：因子／策略取消分别耗时 258.507 ms／243.243 ms，子进程和 Worker 退出码均为 0，Result、checkpoint、pin 均无残留。20 轮成功样本的正常确认和计算路径未变，后续补验不替换其原始数据或耗时。
