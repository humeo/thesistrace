# 03 — 首次压缩后继续回答

**What to build:** Agent Chat 第一次接近模型容量时，在同一 Run 中生成本 Session 的 M/S、一次性保存并继续回答；后续普通消息使用同一固定前缀，压缩失败或取消不会丢失原文或留下半份记忆。

**Blocked by:** 01 — 模型请求预算与明确失败提示

**Status:** ready-for-agent

依据：[spec](../spec.md) 第 1、3—6 节。本票先贯通待压缩历史可装入单批辅助请求的首次压缩；04 在同一路径扩展增量、多批和长轮次。首次生成、存储、调用前调度与继续推理必须一起可验证，不能仅交付数据库结构。

## Acceptance criteria

- [ ] 每次主模型调用前检查完整输入，覆盖新输入、整批工具结果、Continue 和 ask_user 恢复；只有当前模型 C >= K 且 I >= floor(C × 90%) 才正常压缩。最后一条结果和多个工具累计越界均可触发，回答完成且没有待输入时不提前压缩。
- [ ] C >= K 但无合法 D 时允许请求前保护性压缩一次，即使未到 90%；本次已压缩仍不合法则拒绝，不循环。C < K 不执行任何辅助生成，完整历史能容纳就继续，否则通过 01 的错误闭环说明原因。
- [ ] 冻结 checkpoint revision 和消息水位；R 取约 min(20000, floor(T / 2)) tokens 的连续尾部与当前请求、未完成交互等固定保留项的并集，以稳定消息/part 引用去重并按原始顺序排列，保持完整工具配对。E 只包含本次移出的有效原文，排除仍固定条目及无效截断正文。
- [ ] 优先使用 Mastra 已公开的 observer.call / reflector.call 生成候选；先验证现有入口的完成原因、默认工具截断与持久化副作用，仅对实际缺口扩展现有 patch。不经私有方法反射或 as any 绕过契约，候选生成不得提前写入 OM 状态、marker 或通过 extractor hooks 发布内容。
- [ ] Observer 从完整 E 提取 M，保留仍有效的事实、约束、决策及资源引用；M 可为空。M 超过 floor(T / 8) 时在本周期调用 Reflector，目标不超过 floor(floor(T / 8) / 2)；易变执行状态不在 M 维护第二份。
- [ ] S 通过现有 Mastra/AI SDK 使用 Pi 式首次摘要提示词读取原始 E，并以候选 M 作一致性参考；保存目标、约束、进展、阻塞、下一步和准确资源引用、请求 ID、游标、查询条件及错误。可只读引用仍保留的当前请求，但不将其记为已处理历史。S 目标为 floor(T / 16)，不引入 Pi runtime。
- [ ] 所有辅助调用使用当前 Run 模型与 effort，共享 01 的完整请求预算、usage、取消和剩余 Run 时限；不挂载业务工具，不执行被总结内容。文本目标与包含推理的输出额度分别管理。
- [ ] 校验候选结构、S 非空、合法的空 M、关键引用、明确完成原因与文本预算；完整新上下文必须低于 T 且 D 合法。超长候选最多一次纠正生成，长度截断、取消、无合法预算或纠正仍失败时停止，不发布、不借用其他模型或改用另一种算法。
- [ ] 使用现有 Session repository/PostgreSQL 保存 M、S、固定渲染文本、尾部与固定引用边界、处理水位、revision、必要 OM 状态和预算统计；生成期间不持有长事务。提交校验 Session 所有权、revision 与水位，在同一事务原子发布；同一 Session 最多一个有效周期，期间追加的消息继续保留在待处理尾部。
- [ ] 成功提交后，实际主模型请求使用 F + M + S + R + N 并完成回答；失败、取消、M 成功而 S 失败或提交冲突均不推进边界或发布部分摘要，保留原文和上一完整快照，页面明确显示真实失败原因。
- [ ] 采用 thread scope，读写及删除受 Session 所有权约束；同用户其他 Session 也不能获得该 M/S。删除会话一并删除快照，不改变 Core 的 ResearchRun 或 Result Bundle；内部 M/S 不进入浏览器安全投影或常规日志。
- [ ] 关闭原生独立 OM 阈值、后台 buffering、空闲/结束提取及相对日期重渲染。提交时用绝对日期渲染一次，R 不滑动；固定指令和工具确定排序，Run identity 与 Continue 意图每 Run 仅追加一次为内部消息，浏览器不将其显示为用户输入。
- [ ] 加载已提交快照时合并固定引用及边界后的全部有效消息，保持顺序并去重，移除 lastMessages: 50 的额外裁剪；Provider 所需 reasoning/工具协议数据合法重放。连续普通请求不改已发送历史，重启和恢复入口的完整组合验收由 04 扩展。
- [ ] 通过公开 Run 接口以 Scripted/Fake 验证 90% 下方、等于和上方、无合法 D、最后一条工具结果、单批成功与生成失败；使用隔离 PostgreSQL 验证原子提交、revision 竞争、并发追加、提交中断和 Session 隔离，完成对应页面错误测试及 lint/typecheck。记录前后 tokens、usage、耗时及估计偏差，不记录原文或 M/S 正文。
- [ ] 在隔离集成工作区实施并独立 review、提交；本票的单批场景是可验证增量，04 完成前不将其作为完整压缩功能交付。超出已支持范围明确停止，不增加临时 fallback、兼容或迁移路径，不改动 thesistrace-dev 数据。
