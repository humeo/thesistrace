# 05 — 截断后最多恢复一次

**What to build:** 模型因上下文拥挤截断或拒绝请求时，Agent Chat 在允许压缩的模型上最多整理一次并重新生成完整答案；用户能看到截断内容、恢复过程及最终结果，已经成功的研究操作不会重复执行。

**Blocked by:** 04 — 增量压缩与超长历史续接

**Status:** complete

依据：[spec](../spec.md) 第 4、6、7 节。本票复用 01 的结构化停止信息、03/04 的统一压缩控制器和稳定历史，增加有持久化身份的一次恢复及独立替代消息；不再承担首次压缩实现。使用既有工具和 Fixture 可独立验收，新分页契约在 06 汇合。

## Acceptance criteria

- [x] 仅当前模型 C >= K、实际 D 小于 min(P, L)，且 Provider 明确返回 length/incomplete 时尝试长度恢复；不能依据模型正文推测停止原因。Provider 上下文溢出使用同一逻辑步骤的恢复额度，不能换个错误类型再获一次重试。
- [x] 每个逻辑模型步骤最多一次强制压缩并重新生成；逻辑步骤身份、恢复次数、状态和原消息/恢复消息关联写入现有 Session 持久化边界。先占用恢复机会再发起恢复，同 Run 重入、ask_user 恢复或异常分支不能重置计数或并发重复启动。
- [x] 长度恢复前后比较完整输入和受限输出额度，只有上下文实际缩减、D 提高且最终请求合法才重新调用；Provider 上下文溢出同样要求缩减并通过预算保护。成功候选沿用原子提交，不引入另一套摘要算法或独立 OM 调度。
- [x] 已用满完整期望额度、P 小于 L 但已用满 P、无可压缩内容、压缩无改善、候选生成失败、恢复再次失败、取消或时限耗尽均停止。长度不足提示拆分回答，不无限续写；保留 Provider/Run 原有时限，恢复调用共享剩余预算。
- [x] C < K 时无论正常请求、工具批次、Continue、ask_user、无合法 D、上下文溢出还是 length 都不调用 Observer/Reflector/S 或自动重新生成。原快照及完整有效历史能容纳则继续，放不下直接说明原因；不能在恢复分支绕过门槛。
- [x] 本步骤完成原因确认前不释放本地业务工具。对包含完整 tool-call 的截断响应，分别验证恢复、不可恢复及恢复耗尽时本步骤业务执行次数为零；terminal TripWire / isContinued=false 本身不作为安全保证，终止分支使该 LLM workflow stage 明确失败。
- [x] 此前成功执行的工具调用/结果完整配对保留，沿用原请求 ID 和回执；不回放成功操作，不重复提交 ResearchRun，不执行未完成工具参数，也不新增无关业务 command 去重架构。
- [x] 截断可读正文留在持久化审计/UI，排除于有效恢复输入及后续 M/S；成功工具证据单独保留。新模型请求生成完整替代答案，使用独立消息和 supersedes 关系关联原消息，不把半份正文当成已完成事实或让模型从末尾盲目续写。
- [x] 时间线展示恢复中、恢复成功和最终失败；仅在新答案成功完成后标记旧消息已被替代。恢复失败时保留原部分内容及失败原因，不能暗示已有完整答案；刷新页面后持久化状态与展示一致。
- [x] 页面明确区分输出额度耗尽、上下文过大/无法缩减、压缩失败和恢复失败，不展示 Provider 原始错误。已成功的业务回执与 Agent 推理失败同时保留，不能提示用户重复提交；小窗口禁用压缩不显示为正在恢复。
- [x] 不改变现有崩溃生命周期：旧 running Run 重启后失败，不自动恢复执行；新用户请求及停止后的 Continue 是新 Run，不伪装为旧逻辑步骤重试。同 Run 的暂停/恢复保留既有计数，失败仍保留新模型选择、原文与最后成功快照，不回切或裁剪。
- [x] 通过 Scripted/Fake/Replay 测试完整恢复状态机、全额度/部分额度停止、上下文拒绝与长度错误交替、取消、工具零执行和旧成功操作不重放；用隔离 PostgreSQL 验证次数与消息关联，完成相关组件、浏览器截断/替代流程及 lint/typecheck。
- [x] 在同一隔离集成工作区独立 review、提交，记录恢复次数、usage 与耗时等非正文元数据；保留无关工作与 thesistrace-dev 数据，直接接入当前路径，不增加兼容、迁移或崩溃自动续跑分支。完整产品交付由 06 验收。
