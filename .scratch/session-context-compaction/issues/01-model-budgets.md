# 01 — 模型请求预算与明确失败提示

**What to build:** Researcher 选定模型后，Agent Chat 按该模型的真实容量发送合法请求，允许配置范围内的长回答；无法容纳输入或输出被截断时，保留已显示内容并给出准确原因。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

依据：[spec](../spec.md) 第 3、4、7 节。此票贯通配置、实际 Provider 请求、Run 停止原因和聊天错误展示；首次压缩由 03 接入，自动重新生成由 05 接入。没有压缩能力时明确拒绝，不能先永久标记失败再伪装成恢复成功。

## Acceptance criteria

- [ ] 模型配置显式提供并校验 context_window、max_output_tokens；registry 顶层显式提供正整数 min_compaction_context_window，维护值为 65536。Luna 保持 C=258000、L=128000；Provider、Scripted、Eval 与 Fixture 同步当前契约，不补默认输出能力或读取旧配置。
- [ ] 每次按当前 Run 的模型计算 C >= K，验证 65535、65536、65537 及自定义 K。门槛是全局压缩策略，不是输出能力，不新增前端配置面板。
- [ ] 先抽取共用 tokenx 请求计量，再接入预算：计入实际可见的 F、工具定义、M/S、消息、工具参数/结果和必要协议内容；仅排除 Provider 不接收的内部重复副本，不按字段名称误删业务内容。计量缓存不改变原文。
- [ ] 主模型默认 P=L；实际 D 取 P、L 和 C 减完整输入 I 再减 4096 的最小值。通过 Mastra maxOutputTokens 发送，并在 Provider 转换边界重新核验；捕获真实 HTTP payload，验证 OpenAI Responses 携带本次 max_output_tokens，额度包括计入输出的推理和正文。
- [ ] 无合法 D 时不发送该主模型请求，向运行时返回结构化的预算信息；长度停止明确保留完成原因、期望额度和实际 D，能区分上下文挤占与完整期望额度 min(P, L) 耗尽。后续控制器可先处理再确定 Run 终态，错误不再统一归为 AGENT_LIMIT。
- [ ] C < K 时仍进行完整计数和最终预算保护，但不触发原生 OM 或其他辅助压缩；即使 I 达到 90%，只要 D 合法仍可发送。无合法 D、Provider 上下文拒绝或明确 length/incomplete 时终止并说明原因，不自动重新生成。
- [ ] 移除全局 8192 token 与累计生成 256 KiB 的失败规则。合法长回答、工具参数和辅助输出不会被旧限制拒绝；仍记录生成字节数和逐调用 usage，不把累计 usage 当成本次输入。
- [ ] Provider 180 秒、Run 600 秒、取消、权限、协议和传输保护继续有效。当前模型选择不会因调用失败自动回切；错误投影不暴露 Provider 原始错误或敏感内容。
- [ ] 页面保留并标记截断内容，明确区分上下文过大与输出长度不足，并给出选择更大窗口模型、拆分回答或新会话的适当提示；此前工具的业务成功回执与后续 Agent 失败分别展示，不建议重复提交已成功操作。
- [ ] length/incomplete 在本步骤本地业务工具释放前被识别。注入包含完整 tool-call 的截断响应，验证失败分支也不会执行工具；不能只依赖 terminal TripWire 的停止标记。可恢复分支和恢复耗尽的覆盖由 05 扩展。
- [ ] 使用 Scripted/Fake 和本地 Provider Fixture 验证合法长输出、实际请求额度、最后一个大结果及多工具结果的完整计量；通过受影响的配置、模型边界、Run 错误、页面组件测试及对应 lint/typecheck。
- [ ] 在隔离集成工作区提交当前契约及调用方改动，保留无关工作和 thesistrace-dev 数据；不增加兼容、迁移或替代算法。此票独立 review、关闭发现并提交后才可标 complete，整个功能的交付仍受 06 约束。
