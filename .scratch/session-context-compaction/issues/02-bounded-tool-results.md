# 02 — 有界工具结果与完整续读

**What to build:** Agent Chat 查询目录、ResearchRun 或 DailyTrack 时获得准确、有界、可以继续读取的数据；业务操作返回可查询的小回执，研究已经成功不会因附带结果过大被显示为可重试失败。

**Blocked by:** None — can start immediately

**Status:** complete

依据：[spec](../spec.md) 第 8 节。此票贯通 Core 当前工具契约、MCP、Agent 调用与浏览器安全投影；不依赖压缩算法。整批结果触发压缩由 03/04 验证，真实分页与压缩的集成由 06 验证。

## Acceptance criteria

- [x] 明细和列表默认 20 条、最多 50 条；模型可见单页业务 JSON 连同分页元数据不超过 32 KiB UTF-8。以完整记录装页，达到字节预算时减少条目，next_cursor 从实际最后返回条目继续，明确还有后续页。
- [x] 游标绑定可用的身份、查询条件和资源/结果版本；拒绝错误身份、失效或篡改游标、游标与查询条件不匹配。中文及多字节字段按 UTF-8 计量，遍历全部页无遗漏或重复。
- [x] get_alpha_catalog 提供 cursor、limit、next_cursor；limit 计入 fields 与 builtins 的总条目数，使用固定分类及 identifier 顺序，游标绑定查询条件和目录版本。
- [x] get_research_context 为 folders 提供 folder_cursor、folder_limit 和下一页信息；其他上下文信息保留既定契约，Agent 能显式继续读取文件夹集合，不能把首页视为全部资源。
- [x] 单条超长字段通过明确长度契约、声明的字段投影或领域详情读取保持有界。契约与获取完整内容的方式可被调用者理解；不切断 JSON、不静默删字段，也不返回无法前进的空页循环。
- [x] 标准指标摘要完整返回并保持原始数值与精度；完整研究数据保留在现有不可变 Result Bundle 和领域资源中，复用 get_research_run_result、get_daily_track_result 的分节读取，不用模型重写金融数值。
- [x] 写操作仅返回固定的小回执，含执行结果、资源 ID、状态和后续查询方式；成功后不再因附带大明细触发可重试操作失败。通过先成功提交再读取结果的场景验证成功状态和稳定请求身份。
- [x] 保留 Core 256 KiB wire 与 Host 512 KiB decoded response 保护；与 32 KiB 业务页预算分别验证。不新增通用 tool-output artifact、临时文件或重复结果存储。
- [x] Agent 持久化全部工具调用/结果，模型只接收一份 canonical 业务结果，浏览器仍使用安全投影。多工具批次和最后一个结果都完整交给后续上下文组装；工具层不额外丢弃已返回历史。
- [x] 更新受影响的 Schema、权限校验、MCP 描述、调用示例、Scripted 调用与 Fixture。页面能展示分页结果与业务成功回执；后续推理失败不改变 Core 操作状态，配合 01 的错误展示仍保留成功依据。
- [x] 通过 Core/MCP 成功与拒绝契约、UTF-8 页预算、超长单条、游标边界、Agent 工具与相关页面投影测试；实际存储、身份和版本约束使用隔离依赖验证。记录页大小等元数据，不把业务正文写进操作日志。
- [x] 在隔离集成工作区完成并独立 review、提交，保留无关工作及 thesistrace-dev 数据。直接更新当前契约与调用方，不提供旧接口兼容或迁移；整体验收由 06 汇合 01—05 的行为。
