## 已确定的根节点

- 窗口 C 达到 min_compaction_context_window（默认 65536）时启用压缩，正常压缩线为 C 的 90%；C < K 时所有压缩路径禁用。
- 保留独立 M、S 和近期原文；两次压缩之间前缀固定。
- 全部归属 Agent Chat Session，不引入 Researcher 级共享记忆。
- Agent Chat 不是研究结果的权威，遵守 [ADR-0236](../../docs/adr/0236-keep-agent-chat-separate-from-research-truth.md)。
- Agent Host 与 Core 的生命周期、存储边界遵守 [ADR-0235](../../docs/adr/0235-run-the-built-in-research-agent-in-a-separate-host.md)。

## 第一轮决策前沿

### Q1：M 和 S 的职责冲突

原计划让 M 提取任务状态，同时让 S 保存完成/进行中/阻塞状态。两次有损生成可能留下相反的状态，例如旧 M 记载研究仍在运行，新 S 记载已经完成。

推荐：M 只保留仍有效的会话约束、事实与决策；易变执行状态只进入 S。没有应保留的记忆时允许 M 为空。最新权威工具结果优先于旧摘要，修正旧记录不能改变领域结果。保留双层设计，不重新讨论是否删除 M。

状态：已接受。

### Q2：截断后的新答案是替代还是续写

原计划规定 UI 保留截断输出、新消息重新生成，但没有定义截断文本是否继续进入主模型或压缩输入。

推荐：重新生成完整替代答案；截断正文保留在审计/UI，标记为被替代，不作为有效答案或事实写入 M/S。成功的工具调用及结果独立保留。恢复消息明确关联被替代消息。

状态：已接受。已确认本地工具在 output hook 后执行；截断步骤不得释放工具。

### Q3：重启恢复是否包含原 Run 自动续跑

当前 session-repository.ts 的启动处理将运行中的 Run 标记为失败；Continue 仅适用于 stopped Run。原计划的“重启不重置同一步恢复次数”不能直接映射到现有生命周期。

推荐：保持现有生命周期，不新增崩溃自动续跑。重启后下次新 Run 加载已提交的 Session 快照；同一逻辑步骤的自动恢复至多一次，显式新请求与恢复重试分开定义。

状态：已接受。同一 Run 的同一步恢复计数不重置；用户新请求和停止后的 Continue 为新 Run，不伪装为旧步骤自动重试。

### Q4：切换小窗口模型时如何处理过大的旧 M/S

模型配置允许较小 context window。Luna 的旧 M 可达约 29k、S 约 14.5k；它们本身可能超过新模型的窗口，仅分批新历史 E 无法解决。

当时推荐（历史）：支持切换，但使用新选定模型对旧 M/S 按来源分段重新归并，与新快照一起发布。期间不能借用未选定的大模型；失败不发布候选，明确提示此次调用无法继续。另一选择是拒绝无法容纳现有记忆的模型切换。

状态：已被压缩启用门槛规则取代。删除模型切换专用的旧 M/S 分段重整；C < K 时完整上下文能容纳就使用，否则明确报错。满足门槛时保留普通压缩，无法进入合法辅助请求则明确失败，不借用其他模型。

## 第二轮决策前沿

### Q5：小模型重整失败后是否保留新模型选择

当时讨论基于 Q4 的分段重整方案；该路径现已移除。模型选择与快照提交仍须分离，不能因上下文不足或压缩失败自动回切模型。

保留的决定：保留用户的新模型选择，本次 Run 明确失败；旧快照不变，下次请求继续用所选模型处理。界面按实际原因显示上下文不足或压缩失败，不暗示切换已完成推理，也不自动切回原模型。

状态：已接受。

## 工程事实与后续分支

- installed Mastra 已公开 ObservationalMemory.observer / reflector 和 call()；不能将“没有候选入口”作为必须新增 API 的前提。仍须核查完成原因、默认截断、extractor hooks 与 marker 写入；仅针对实际缺口 patch。
- 已按 Q1 修正非空校验；空 M 不等于生成失败。
- 约 20k 近期尾部与必须保留项不是同一个预算；超大最新输入、完整工具组和模型切换后的容量不足需要明确可压缩边界。
- 压缩辅助调用计入既定 Run 时间预算，生成批次数与剩余时间的工程约束需要补齐，不能把单次 180 秒误当完整周期预算。
- 当前 Mastra 本地工具执行位于 output hook 之后；不能从 tool-call 流事件推断已执行。有效 retry 会清空本步骤工具，但 terminal TripWire / retry 耗尽未保证清空；终止路径必须使 LLM stage 失败并实测零执行，无需新增业务 command 去重系统。
