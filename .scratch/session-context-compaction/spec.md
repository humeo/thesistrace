# Session 上下文压缩与工具输出预算

**Status:** complete

更新时间：2026-09-07。六项实现票已独立提交并完成验收；需求正文保留，最终版本、分阶段复验结果及诊断限制见 [evidence-06](evidence-06.md)。

## 1. 最终上下文结构

```text
固定指令和工具 F
+ 当前 Session 的固定记忆 M
+ 当前 Session 的固定会话摘要 S
+ 本次压缩保留的近期原文 R
+ 后续只追加的消息 N
```

- M 与 S 是两个独立产物，都归属于当前 Session。Mastra 使用 `scope: "thread"`；用户身份仍用于权限校验，不作为共享记忆键。
- M 保存当前 Session 内需要跨多次压缩保留的事实、约束、重要决策和资源引用；复用 Mastra Observer/Reflector 的提取、追加、反思过程。
- S 保存本次任务的目标、已完成/进行中/阻塞状态、下一步和恢复执行所需上下文；采用 Pi 的首次/增量更新摘要及长轮次前缀摘要模式。
- 同一项事实只保留必要的重复。M 负责持久事实，S 负责当前执行状态；S 中不能省略恢复任务必需的约束、资源 ID 和失败原因。
- 易变的执行状态只进入 S，不在 M 维护另一份状态；最新权威工具结果优先于旧记忆。没有需要保留的事实时 M 可以为空，不能因此判定压缩失败。
- M、S、R 在两次压缩之间保持内容和顺序不变，N 只追加。约 20k 的 R 是压缩时选定的保留区，不是每次请求重新滑动的窗口。
- 首次压缩之前，M、S 可以为空；所有已有消息按原有顺序进入 N。

不实现用户级共享记忆、其他 Session 的记忆/消息注入、空闲或会话结束时的记忆提取，以及独立的用户记忆同步 Worker。另一个 Session 从自己的历史构建 M/S。

## 3. Token 预算与模型配置

唯一模型能力来源为 `config/model-registry.json`，运行时读取已校验的配置：

- `context_window`：当前部署允许的上下文窗口 C；Luna 保持 258,000。
- `max_output_tokens`：必填、合法的模型输出能力 L；维护的 Luna 配置为 128,000。缺失或非法时拒绝配置，不补全为 8,192。
- `min_compaction_context_window`：registry 顶层的压缩启用策略 K，适用于所有模型，维护默认值为 65,536。配置显式提供并校验为正整数；它不是模型能力，也不增加前端配置面板。
- 所有 Provider/Scripted/Eval 配置和 Fixture 同步硬切换，不引入旧配置兼容读取。

```text
T = floor(C × 0.90)                    正常压缩线
K = min_compaction_context_window     压缩启用门槛，默认 65536
compressionEnabled = C >= K           等于门槛时启用
正常压缩条件 = compressionEnabled && I >= T
H = 4096                              请求预算的安全余量，不是压缩触发线
I = 本次完整模型输入的 token 估计
D = min(P, L, C - I - H)               实际请求的 maxOutputTokens
```

P 为本次调用希望使用的生成额度。主模型默认 P = L；压缩调用按其任务预算申请。D 需要实际传给 Provider，OpenAI Responses 对应 `max_output_tokens`；该额度包含模型计入输出的推理和正文。

I 包含 F、工具定义、M、S、R、N、工具参数/结果及模型所需协议内容。继续使用项目已有 tokenx，与模型可见结构一致；压缩决策和最终请求保护共用计数函数。排除不会发送给 Provider 的内部重复副本，不能把有意义的工具字段按名字随意排除。保存原文 token 估计缓存，不修改模型可见内容。Provider usage 用于校准与核对，不能把跨调用累计 usage 当成本次输入。

内部文本预算：

| 项目 | 规则 | Luna 数值 |
| --- | --- | --- |
| 压缩启用门槛 K | min_compaction_context_window，全局策略 | 65,536；Luna 满足门槛 |
| 正常压缩线 T | floor(C × 90%) | 232,200 |
| 近期原文目标 R | min(20,000, floor(T / 2))，按完整消息/调用组选择 | 约 20,000 |
| M 的反思触发预算 | floor(T / 8) | 29,025 |
| M 的反思目标 | floor(M 预算 / 2) | 14,512 |
| 新增 S 的目标预算 | floor(T / 16) | 14,512 |

M/S 目标是最终注入文本的预算，不等同于包含推理的模型生成额度。选择生成额度时需要为推理和输出预留空间，生成后重新核算文本和完整上下文。S 预算是本版新增的内部策略；不增加用户配置面板。

这些文本预算约束新生成的快照。切换模型后不立即按新预算改写旧 M/S；旧快照能进入完整合法请求时直接复用。无论是否启用压缩，完整输入计数、动态 D 和最终 Provider 预算保护都继续执行。

压缩完成后完整输入必须低于 T，并有合法的 D。若固定内容、当前输入或必须完整保留的工具组已经无法容纳，返回明确的上下文过大错误，不反复压缩、不静默丢消息。

移除全局 8,192 输出限制，以及累计生成 256 KiB 就失败的限制。生成字节数继续作为计量；保留当前 Provider 180 秒、Run 600 秒、取消、权限、协议和传输保护。压缩调用同样计入当前 Run 的时间、取消与 usage。

## 4. 何时检查

1. 新用户输入、Continue、工具恢复或 ask_user 恢复，在下次主模型请求前检查完整输入。
2. 一轮模型响应和工具执行结束后，先持久化完整工具调用/结果；若还需要推理或处理待输入消息，在下次主模型请求前检查。
3. 已完成回答且没有待处理输入时，不为下一轮提前压缩；下次需要推理时检查。

正常条件为 compressionEnabled && I >= T。多个检查点由同一个控制器决策；同一 Session 同时只能有一个有效压缩周期。每次按本次 Run 的模型配置计算 C >= K，不因 Session 曾用大窗口模型而继续启用压缩。

仅在 compressionEnabled 为 true 时，除正常阈值外保留明确的请求保护与恢复例外：

- 请求前没有合法的 D 时，先尝试一次压缩，重新计数仍无法容纳就明确拒绝调用；本次已经压缩且结果无法容纳时直接拒绝，不再次循环。即使 I 尚未达到 T，也必须执行此保护。
- Provider 上下文溢出，以及因剩余上下文使 D 缩小而发生的 length/incomplete，可按第 7 节强制压缩并最多自动恢复一次。

这些是请求保护或失败恢复，不构成另一条正常压缩线。

### 小窗口模型：C < K

- 不调用 Observer、Reflector 或会话摘要模型；正常阈值、无输出空间保护、Provider 上下文溢出和长度截断都不能绕过该门槛触发压缩。
- 使用已有 M/S、固定保留项、完整有效尾部及新消息；尚无快照则使用原始有效历史。不静默丢弃 M/S、裁剪消息或额外采用滑动窗口。
- I 即使达到或超过 T，只要 D 合法仍可继续调用；90% 不是小窗口模型的停止线。
- 无合法 D 时直接拒绝主模型调用。Provider 上下文拒绝或 length 停止时明确终止，不进行压缩或自动重新生成。
- 页面提示当前模型无法容纳此会话或输出未完成，引导选择更大窗口模型、拆分回答或新建会话；保留历史、旧快照和用户的新模型选择，不自动回切。
- 工具已成功但后续推理无法继续时，保留并展示业务成功回执，另行标明 Agent 推理失败，不能把业务操作显示为失败或建议重复提交。

不启用 Mastra 原生独立阈值触发、后台 buffering、相对日期重渲染或空闲激活路径来修改已发布前缀。

## 5. 一个压缩周期内做什么

本节仅在 C >= K 且第 4 节正常触发或有界恢复条件成立时执行。

1. **冻结输入范围。** 读取当前 checkpoint revision 与消息水位。新到达的消息可以排队，但不改变本周期正在处理的原文范围。
2. **选 R 和待压缩区 E。** R 为约 20k 连续尾部与固定保留项（当前用户请求、未完成交互）的并集，按原始顺序排列，以稳定消息/part 引用去重，保持调用与结果配对。E 为上一快照有效原文及新增消息中本次移出的部分，排除仍固定保留的条目及无效截断正文，不重复加入已经处理的原文。固定项只在下一次压缩重新判定；解除固定且落在尾部之前时才进入 E。生成 S 时可只读引用当前请求以补齐目标，但不能将该引用标记为本次已移出历史。
3. **产生候选 M。** 将旧 M 和 E 中尚未观察的原文分批交给 Mastra Observer，追加新增观察。每批合并后重新检查候选 M，超过预算就在本周期调用 Reflector 压缩至目标范围；未超过则不调用。这一步只精简 M，不替代 S。
4. **产生候选 S。** 使用旧 S、E 的原始消息和候选 M 作为一致性参考，生成新的任务交接摘要。摘要必须阅读原始 E，不能只对已经有损的 M 再总结。首次无旧 S 时用首次模板，后续用更新模板。
5. **处理长轮次。** 若保留边界落在一个很长的任务轮次中，对更早历史和该轮次前半段分别摘要；合成一份 S，为保留的后半段补齐原始请求、进展和必要前情。原始工具调用/结果仍保持完整配对。
6. **检查候选。** 校验 S 非空与结构、M 的合法结构（允许没有记忆）、关键资源引用、完成状态、目标文本预算及完整新输入预算。被 Provider 截断的半份摘要不允许提交。超长输出最多进行一次纠正生成，失败则终止本周期。
7. **一次性发布。** 固定渲染 M、S，和 R 的边界一起原子提交到当前 Session，然后继续主模型请求。中间批次、反思输出和半份 S 都不会进入主模型上下文。

### 分批和大内容

- 每个 Observer、Reflector、摘要请求，都先计入自己的 system 指令、旧记忆/摘要、选中消息和生成余量，再决定本批大小。
- 不新增模型切换专用的旧 M/S 分段重整流程。C >= K 时仍可按普通流程压缩；若旧 M/S 本身无法进入合法的辅助请求，则明确失败，保留旧快照，不借用其他模型。以下普通历史分批与单条待摘要文本分段规则继续保留。
- 当前安装版本的 Mastra 单 thread 同步路径不会自动按 10k 分批。需要在现有集成中增加受控分批调用，不依赖未经验证的库行为。
- 一批必须在有效消息边界结束；主模型历史中的工具调用与结果不能被拆开。若某条待摘要文本单独超过摘要请求预算，可以仅在摘要输入中按带来源标识的文本片段分批提取，再合并；原始会话条目不变。
- 持续记录各批处理到的原文位置，直到覆盖全部 E；不能因为分批只保留了第一段或丢掉后段错误信息。
- 不把 Mastra Observer 的单工具约 10k token 截断，或 Pi 序列化工具结果的 2,000 字符截断，当成完整输入控制方案。正常工具内容先由第 8 节的分页约束，压缩输入超预算由本节分批处理。

### 模型调用与提示词

- M 复用现有 Mastra Observer/Reflector 的提示词、解析能力，采用本方案的受控调度和请求预算。提取当前 Session 仍有效的事实、约束、重要决策和资源引用；执行状态、请求 ID 与续读游标由 S 保存。辅助 continuation hints 不作为另一份动态 S 注入主模型。
- S 使用独立摘要 system 指令，只生成摘要、不执行被总结的任务、不挂载业务工具。复用现有 Mastra/AI SDK 调用与统一 usage/取消边界，不引入整套 Pi coding-agent runtime。
- S 的结构沿用 Pi：目标、约束与偏好、进展（完成/进行中/阻塞）、关键决策、下一步、关键上下文。保留准确的 ResearchRun/Result/数据版本 ID、请求 ID、续读游标及绑定的查询条件、参数、错误信息和其他续接依据。
- 两者都使用当前 Run 已选定的模型/effort，不偷偷切换其他 Provider。首次、更新和长轮次提示词的原文来源见研究笔记；具体领域调整需要固定案例评估。

## 6. 前缀与持久化

```text
周期 k 发布：F + M_k + S_k + R_k
后续请求：  F + M_k + S_k + R_k + N_1 + N_2 + ...
周期 k+1：  F + M_(k+1) + S_(k+1) + R_(k+1)
```

- 指令、工具定义及顺序保持确定。日期用固定绝对时间；Run ID、Continue 等每次变化的控制信息从静态 system 移到有稳定身份、每次运行只追加一次的内部会话消息位置。恢复时不重复追加，浏览器不把这些内部控制信息显示为用户消息。
- 用户切换模型或实际工具定义/权限变化时，重新校验模型预算和可用工具。这是允许前缀变化的明确边界，不能为命中缓存保留已撤销权限或过期工具定义。
- 模型切换后重新组装并检查完整上下文。C < K 时只复用能容纳的旧快照与有效历史，放不下就明确拒绝；C >= K 时遵循普通压缩与请求保护规则，不单独重整旧 M/S。模型选择与快照提交分离：失败保留用户的新模型选择及旧快照，按实际原因显示上下文不足或压缩失败，不自动切回原模型；下次请求仍使用所选模型。
- 不改写已经发送的原文或工具结果，不每次重新序列化出不同前缀。Provider 需要的 reasoning/工具协议数据同样遵守合法且稳定的重放契约。
- 每个 checkpoint 至少保存 M、S、固定渲染文本、连续尾部边界、固定保留引用、处理水位、revision、预算/usage 信息和必要的 Mastra observation 状态。边界使用稳定消息 ID；单消息含多次追加 part 时带稳定 part 边界。
- 存储使用现有 PostgreSQL/Session repository。生成期间不持有长数据库事务；最终用 revision/水位校验和同一事务提交 M/S、边界及相关 OM 状态。失败、取消或候选仍超预算时不推进边界、不发布部分摘要；保留原始消息和上一个完整 checkpoint，当前 Run 明确报告压缩失败或取消，不偷偷使用另一种算法继续。
- 优先复用 Mastra 已公开的 observer.call / reflector.call；只针对完成原因透传、默认工具截断、extractor hooks 与 marker 写入等实际缺口扩展现有 patch，并验证纯候选行为。不能因已有 call 便假设无副作用，也不通过私有方法反射或 `as any` 绕过状态提交边界。
- 重启、Continue、工具恢复及 ask_user 恢复时，载入最后成功快照、全部固定保留引用及连续尾部边界之后的有效消息，并按原始顺序去重；不能让 `lastMessages: 50` 额外裁掉保留历史，也不能让原生自动 OM 再压缩一次。
- 重启恢复指恢复会话上下文，不新增崩溃后原 Run 的自动续跑。保留现有启动时将运行中 Run 标失败、Continue 仅接受主动停止 Run 的生命周期。
- 保留本 Session 原始历史；删除 Session 时一并删除其 M/S。内部记忆与摘要不直接进入浏览器安全投影或常规日志。
- 缓存验证既比较相邻主模型请求的可复用前缀，也记录 Provider 的 cached_tokens；相同前缀是可复用条件，不承诺每次请求都命中。

## 7. 输出停止与一次恢复

- Provider 的 length/incomplete 必须成为明确的完成原因，不能仅凭模型生成文字判断它是否“还想继续”。
- 只有 C >= K、D < min(P, L)，且 Provider 明确返回长度停止时，才进行因上下文拥挤而触发的长度恢复。同一存活 Run 的逻辑模型步骤最多强制压缩并重新生成一次；恢复次数和步骤身份持久化，同一 Run 的 ask_user 恢复不重置既有记录。新用户请求及主动停止后的 Continue 属于新 Run，不视为崩溃步骤的自动重试。
- 压缩后必须实际缩减上下文，并提高受上下文限制的 D，才能重新请求；没有改善、恢复仍失败或取消时立即停止恢复。Provider 上下文溢出的恢复同样要求 C >= K，必须缩减上下文、通过完整预算检查，并受同一逻辑步骤的恢复次数限制。C < K 时两种情况都直接终止，不调用压缩模型。
- 成功工具调用及结果成对保留，沿用幂等请求 ID；不回放已完成操作、不重复提交 ResearchRun，不执行不完整工具参数。
- 本步骤模型完成原因确认前不释放本地业务工具；length 被恢复、不可恢复及重试耗尽三条路径都必须保证该步骤工具不执行。当前 Mastra output hook 先于本地工具执行，但 terminal TripWire / 重试耗尽不保证清空工具列表；终止时使该 LLM workflow stage 明确失败，不能仅依赖 isContinued=false。
- 若 D 已经达到完整期望额度 min(P, L)，仍发生长度停止，明确提示需要拆分回答；不通过反复压缩历史或无限续写重试。
- UI 保留并标记截断的可读输出，显示正在恢复、恢复成功或最终失败状态。重新生成完整替代答案，用独立消息和 supersedes 关系关联原消息；旧截断正文只保留审计/UI，不进入恢复模型输入或 M/S。此前成功的工具调用及结果单独保留。新答案成功后标明旧消息已被替代；恢复失败时不能暗示已有完整替代答案。最终错误明确区分输出上限、上下文无法缩减和恢复失败。
- 总输出字节只计量，不用另一个 256 KiB 总量上限把合法长回答、工具参数或压缩输出误判为 AGENT_LIMIT。

## 8. 工具输出方案继续纳入本次交付

- Core 的明细/列表读工具采用默认 20 行、最多 50 行的分页；模型可见每页业务 JSON 含元数据不超过 32 KiB（UTF-8）。到达字节预算时减少本页条目，返回完整记录，游标从实际最后返回条目续接。通过 next_cursor 等分页契约明确还有后续页，不能把一页描述为全集。
- 游标保留现有身份、查询条件与结果版本约束。单条记录的长字段必须有明确长度契约；需要时用显式字段选择或领域详情读取，让列表记录在声明的投影内完整且有界。不能仅靠减少行数处理超大单条记录，也不能切断 JSON 或静默省略字段。
- 标准指标摘要完整返回，领域数值不得为缩短长度而改变精度或用模型总结替代计算结果。巨大研究数据保留在现有不可变 Result / 领域资源中，复用 get_research_run_result、get_daily_track_result 等分节读取工具。不要新建泛用 tool-output artifact 系统或重复结果存储。
- 写操作返回固定的小型执行回执，包含执行结果、资源 ID、状态及后续查询方式。已成功的业务操作不能因附带大结果超过响应预算而变成可重试的操作失败；大内容通过领域读取路径访问。
- `get_alpha_catalog` 增加 limit/cursor/next_cursor，游标绑定查询条件及目录版本；`get_research_context` 的文件夹集合增加 folder_limit/folder_cursor 及下一页信息。相关契约、示例和 Scripted 调用一起更新。
- 多工具同一步按结果总预算处理，不能只验证单个结果。工具组完整持久化后，在下一次模型调用前重新计数；需要时仅在 C >= K 下压缩更早上下文。C < K 时直接检查请求能否容纳；若完整的必须保留组仍无法装入，明确拒绝继续，禁止无限压缩或丢弃部分结果。已成功操作的回执与 Agent 后续推理失败分别展示。
- 保留 Core 256 KiB wire 和 Host 512 KiB decoded response 保护，它们是传输边界，与 32 KiB 模型页预算不同。
- 模型上下文只包含一份 canonical 工具结果；计量排除 Mastra 内部重复元数据，浏览器继续只接收既有安全结果投影。

- 实际 Provider payload 包含本次 D，合法输出超过 8,192 tokens / 累计 256 KiB 不再被旧限制拒绝；同 Run 的每个逻辑步骤最多恢复一次，同 Run 恢复不清零，重启不自动续跑。压缩无改善、已用满期望额度或取消时不再恢复。
- 空 M 合法；旧 M/S 无法进入新模型的合法请求时不启动专用分段重整，普通压缩无法处理则明确失败且旧快照不变；边界前固定用户请求在恢复时不丢失，解除固定后只处理一次。截断替代答案不读取旧半份正文，所有 length 终止分支均不释放本步骤业务工具。
- 分页游标和过滤条件正确，错误身份或无效游标被拒绝，页字节达标且无遗漏/重复；完整指标摘要、超长单条字段和写回执均满足契约；成功操作不因附带结果过大变成可重试失败。
