# Agent 可调用的研究验证能力：MCP 契约方案

状态：设计建议，未实现、未发布。现有工具根据本轮实际可调用元数据与当前registry/models核对；新工具、新参数、新section均不是目前可直接调用的API。

## 共同原则

网页HTTP入口和Agent MCP入口调用同一研究、诊断和比较应用服务，使用同一数据版本、账户规则及指标口径。MCP返回结构化研究事实；网页呈现这些事实。不要让Agent操作页面才能取得完整结果，也不要将确定性指标和跨实验可比性判定重新交给模型计算。

对Agent来说，完整能力包括：发现可用输入、预检完整请求、提交明确实验、观察执行、读取可解释结果、比较条件、继续追踪。现有系统已具备这条链路的大部分工具，不需要另建一套Agent研究引擎。

## 当前已可调用的能力

- get_research_context：Data Overview与研究约束。
- get_alpha_catalog：字段、单位、财务报告期/可见时间、缺失行为及算子。
- diagnose_alpha_formula：只检查source公式，不包含完整日期/账户/批次容量预检。
- submit_research_run：单次因子/策略；策略只接受持仓数与调仓间隔等现有字段，未开放本金/费用/账户范围/来源。
- submit_research_batch：factor_evaluation或strategy_sweep。strategy_sweep共享公式、日期、股票池和中性化，每项只变持仓数/调仓间隔；不能直接传不同起止日期。
- get_research_run / get_research_batch：持久执行状态与建议轮询间隔，和结果读取分离。
- get_research_run_result：当前section为factor、strategy_summary、strategy_observations、terminal_strategy_state、terminal_positions、provenance。factor已有q1-q5与总体覆盖；没有逐组有效日、完整TopN诊断和历史逐笔交易账本。
- start/get/get_result/refresh/retry_daily_track：既有后续跟踪能力。

工具集受权限过滤；上面是本会话实际看到的能力，不把registry中未暴露给本会话的管理操作称为当前可调用。

## 建议接口映射

|能力|接口设计|Agent得到什么|
|---|---|---|
|发现能力|扩展get_research_context和get_alpha_catalog|支持的本金/成本/账户选项、结果section、分页与批次数量上限、已发布日期；参数有明确类型与范围|
|完整预检|新增preflight_research|固定待用数据版本、所需字段/历史、覆盖诊断、数据时效、结构化阻塞原因；估算与已知资源限制明确区分|
|真实账户及因子来源|扩展submit_research_run|initial_cash_cny、受支持的account_constraints与costs；来源Result关系和明确数据选择；返回已冻结的实际条件|
|因子诊断|扩展get_research_run_result的factor，增加factor_diagnostics section|逐组/配对有效日、平均股票数、TopN未来收益及样本/标签口径；可分页读取支持解释的日级事实|
|账户解释|增加strategy_ledger等结果section|信号、目标/实际数量、成交、拒单原因、现金、费用及合成结算调整，按公开模型可独立对账|
|跨条件提交|扩展submit_research_batch增加明确的strategy_comparison种类|来源策略与显式cases，每项有独立账户输入和Run；继续用get_research_batch观察|
|跨结果比较|新增compare_research_runs|固定条件、实际变化、额外混杂差异、每项状态/指标/来源、样本长度及比较限制|
|持续验证|扩展现有DailyTrack对新账户契约的继承|真实继承源本金/账户/费用和数据/执行语义，区分不可变起点与后续观测|

工具名称和字段命名是提议。采用当前契约的显式演进，不增加运行时旧版本兼容分支；如涉及已有数据升级，遵循仓库要求进行保留数据、可验证的显式迁移。

## 来源与冻结条件

“来源因子/策略”不是自由文本标签。服务端应解析并授权检查源Result，保存来源关系以及用户声明的变化。全新公式提交和从源结果继续研究应有清楚的输入形式；来源引用与重复显式字段冲突时拒绝，不让服务端或Agent暗中选择一方。

比较实验默认固定同一Data Generation及执行契约；显式选择新版本时记录差异，不能仍标成同条件。若旧版本无法用于新研究，明确拒绝，不能静默使用最新版本。公式、日期、Universe、中性化、标签期、账户与费用等关键条件都在结果中可读。

## 因子诊断应返回的事实

- 每个预测期的信号日期范围、有效样本和未来收益标签定义。
- q1-q5各自的平均标签收益、有效日数、平均股票数、空组原因。
- top_bottom按同时有效日配对计算的样本与收益，不能只给两个组均值相减。
- 预先声明的Top10/20/100诊断，说明股票集合、排名方向、并列处理及日级/调仓日采样；这是标签统计，不等同实际账户收益。
- 来源数据不足、主动条件排除、未来标签尚不完整，使用不同reason_code，缺失为null且保留原因。

诊断应在研究执行时按声明的范围计算并冻结；读取结果工具不偷偷修改既有Result或启动昂贵新回测。新增任意TopN等需求若需要额外计算，应显式提交新研究，并保留来源。

## 跨日期/成本实验不是现有strategy_sweep的隐式扩张

当前strategy_sweep以共享日期为前提。建议新增明确的strategy_comparison批次种类，使用来源策略与有限、显式case列表，由持久服务创建并运行各个独立账户。沿用请求幂等、按项状态和稳定关联，不另建一整套实验管理系统。

case应包含用户选择的变化，例如start_date、end_date、initial_cash_cny、cost scenario；不默认生成未展示的笛卡尔积。先做完整参数、权限和容量准入，再接受有限任务；accepted仅代表接受。调度层保留原条件，不能因为资源不足减少股票池或历史。

“同一个批次”只说明实验组织与调度关系；不同起点不能宣称共享了全部Alpha/Factor计算。复用状态必须由执行层提供，明确actual复用了什么；该组的计数不能当独立经济家族数。

在新增批次种类之前，Agent可以使用现有单Run入口分别提交其当前支持的日期条件，再取回结果；但这不等于产品已经提供持久的跨条件比较批次，也不解决当前本金等未开放参数。

## 比较返回与语义

compare_research_runs先返回有界摘要，包括每行run_id、状态、起止日、样本长度、本金、实际变化、收益/回撤/Sharpe/费用/现金和来源。历史账户指标是研究事实；是否值得选择由用户/Agent结合目标判断，产品不直接宣称“推荐投资”。

以指定比较维度区分预期变化和额外差异。例如本金本来就是比较维度时不应一律拒绝；公式、数据版本或账户模型意外不同则提示不能归因为本金。不同起点的结果保留期限差异，不能只按累计收益排出无条件优劣。

明确区分：
- continuous_window：同一个原账户的区间观察；沿用已有持仓状态，区间指标使用公开且一致的定义。
- independent_restart：独立重新建仓；必须来自真实新账户Run。
- walk_forward：另需预声明选择/训练和测试窗口；第一版多日期比较不冒用这个标签。

详情通过分页section读取；不把多年日级与逐股数据一次塞进工具结果。比较输出必须绑定不可变结果，不能在翻页时混入另一版数据。

## Agent应“看见”的错误与状态

除了文字说明，返回code、field/item_key、expected/actual、retryable、当前阶段、已完成/总计、retry_after_seconds、相关run/batch及trace引用。受控资源诊断只返回实际可取得的预算/使用证据；未知根因明确未知，不猜OOM。

preflight是当前版本的可执行性检查和估算，不保证未来资源被预留；真正提交仍做准入检查。预检不创建Run，不产生隐藏研究任务。

缺失/失败不返回伪造的0；成功、部分失败、全部失败、结果不可用明确区分。已有accepted、replayed、request_id及轮询间隔应保留，Agent不因一次工具超时重复提交新任务。

## 最小验收

1. 纯MCP客户端无需浏览器，完成选字段→预检→真实10万元策略→读取因子诊断/账户结果→多起点比较。
2. 同一请求从HTTP或MCP提交，冻结条件与计算语义相同；状态码和字段限制可预测。
3. Agent能识别数据版本差异、未完成/失败、空分组、不同样本长度与账户模型，而不是推测。
4. 因子来源、比较case、真实Run和结果可双向追溯。
5. 幂等重放不重复创建任务；分页绑定结果、无遗漏重复；工具描述和schema公开边界。
6. 工程用固定数据/Replay验证契约；真实Agent效果另测成功率、工具调用数、token、时延与错误恢复，不用单次模型演示代替工程验收。
