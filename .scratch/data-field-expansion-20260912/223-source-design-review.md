# 223 字段设计：daily_basic 与 fina_indicator 来源约束

核查日期：2026-09-12。范围固定为已确定的 223 字段；本次只读取官方文档和已有证据，没有请求真实 TuShare API。以下将供应商声明与本项目应采用的设计约束分开。

## 已确认的来源边界

| 来源 | 官方采集合同 | 没有获得的保证 |
| --- | --- | --- |
| [daily_basic](https://tushare.pro/document/2?doc_id=32) | 可按交易日取横截面，或按证券和日期范围取历史；单次最多 6000 行；交易日 15–17 点更新；2000 积分起，5000 积分无总量限制。 | 没有明确统一历史起点、逐列覆盖起点、修订时间或稳定分页游标；输入表未声明 `offset` / `limit`。更新窗口不是每个证券必在 17 点完整到达的 SLA。 |
| [fina_indicator](https://tushare.pro/document/2?doc_id=79) | 普通接口按单只股票取历史，最多 100 行；`start_date` / `end_date` 按**报告期**筛选，另有 `period`、`ann_date`。普通接口 2000 积分起；VIP 支持某季度全市场，需 5000 积分。 | 未给出 VIP 独立行上限、可靠分页合同、逐列历史起点或历史修订全集承诺；不能将普通接口的单股能力推定为全市场批量能力。 |

[官方更新总表](https://tushare.pro/document/1?doc_id=108) 将财务指标描述为覆盖全部历史、随财报更新，但没有给数值化延迟或统一最早日期。它不能证明本次目标自 2010 年起，每个证券的每列都已具备历史数据。

已有[保存的探测结果](live-tushare-field-probe.json)只证明：`600519.SH` 的一个交易日返回 daily_basic 19 列；一个年报期返回 fina_indicator 167 列，其中非空列总数为 162，包含元数据。它不证明分页、历史修订、季度数据、单位或全市场非空覆盖。当前[字段 schema](official-field-schema.json)是 16 个 daily_basic 浮点列与 163 个 fina_indicator 浮点列；其余日期、代码、更新标记不计入研究字段数量。

## 应写进新版的采集与完整性约束

以下是设计建议，不是供应商额外承诺。

1. **按来源自然颗粒分片。** daily_basic 首选一个交易日一个分片；遇到行数达到上限或范围对账不通过，按已保存的历史证券范围进一步拆到证券与日期。fina_indicator 首选证券与报告期，不能用“最近 100 条”作为历史回填，也不能假设一个报告期只有一行。所有目标列和元数据显式列入 `fields`，不依赖默认输出。
2. **满额响应必须保持未完成。** 达到 6000 / 100 行要记录可能截断；分片已经足够小时仍满额，不能靠截取、去重或加一个未经验证的 `offset` 宣告成功。只有经验证的请求合同才能继续细分或分页。少于上限仅消除这一种截断迹象，仍需检查证券/日期/报告期边界、重复、返回字段与来源错误。VIP 若采用，应独立验收其实际合同。
3. **将请求完成和覆盖完成分开。** 记录每个分片的请求参数、采集时间、原始响应摘要、行数、去重后行数、边界及是否触及上限；另做证券、字段、期间的可用性统计。历史范围来自存续证券资料，不能只循环今天仍上市的名单。未上市、不适用、来源空值、尚未披露、请求失败、疑似截断不能都归成“缺失并填零”。
4. **增量必须能够发现旧报告期的变化。** fina_indicator 的报告期筛选不能充当公告时间游标。应重查近期报告期并周期性复核旧报告期，保存内容变化；不能承诺固定滚动窗口能发现所有迟到修订。完成水位表示已检查的范围，而不是“此范围永远不会变化”。
5. **更新窗口只决定何时尝试采集。** 日频指标在窗口后采集，并以实际覆盖与来源状态决定是否发布；财务更新采用有边界的重试与复核。不能因为到达计划时间、请求成功或某一行到达，就推进整个家族的完成水位。出现更正时保留旧 Generation 及来源证据，以新版本发布。

## fina_indicator 的身份与 PIT 边界

官方输出只有 `ts_code`、`ann_date`、`end_date`、`update_flag` 四个非数值字段；没有三表的 `report_type`、`comp_type`、`f_ann_date`，也没有修订时间戳。`update_flag` 只被描述为更新标记；官方样例还有相同证券、公告日、报告期重复的记录。[fina_indicator 文档](https://tushare.pro/document/2?doc_id=79)

据此建议：

- 使用财务指标自己的来源记录合同，保留上述元数据以及响应/内容哈希、首次观察时间、采集批次；**不补造** `report_type=1`、`comp_type=1` 或 `f_ann_date=ann_date`。`update_flag` 不作唯一版本号或时间排序依据。
- 相同证券、公告日、报告期不能直接视为唯一行。完全相同的内容可以幂等合并证据；不同内容必须保留。若同一可用日期内存在冲突且没有可证明的先后，显式记录冲突，不能依赖响应顺序任取最后一行。
- 分开保存报告期、供应商公告日、系统观察时间与研究可用交易日。报告期是数值所属期间，不是可交易日期；公告日缺失或无效时，不能改用报告期补齐可用时间。
- 对只有日期的公告，日频设计可以明确采用公告日之后的首个交易日作为保守的公告滞后规则；daily_basic 当日收盘后到达的值也不能用于同日收盘成交。规则须与研究决策时点一致，但这种日级滞后仍未证明供应商当时已经提供同一个数值。
- **历史回填只能声称按供应商公告日期作了滞后投影。** 今天抓到的旧报告不能证明它是当时未被更正的版本。完整 PIT 还要求当时版本、实际可得时间和修订链证据；本系统开始持续留存后的观察证据，只能证明自身观察到的版本，不能倒推更早历史。
- 公司类型适用性单独建证据与规则：如利用已有三表元数据，应保留其来源及关联期间，关联失败明确为未知。不能把缺少公司类型当成普通工商企业，也不能把今天的分类回填成全历史分类。

## 单位与语义：必须逐列锁定，不能批量猜测

| 情况 | 本轮设计约束 |
| --- | --- |
| daily_basic 股本、市值、股息率 | 文档明确股本用万股、市值用万元、两项股息率用百分数；规范化分别写明倍率。换手率当前文字没有明确百分数缩放，不能仅凭列名自动除以 100。[官方定义](https://tushare.pro/document/2?doc_id=32) |
| fina_indicator 金额与比率 | 文档并非逐列给单位。很多增长字段明示百分数，但 `equity_yoy` 等没有显式缩放；金额、每股值、倍数、百分数不可统一处理。保留供应商原值；单位未核实时标记来源单位待核实，不能宣称已经统一为元或 0–1 比例。[官方定义](https://tushare.pro/document/2?doc_id=79) |
| 数字可返回，不代表定义可任意推导 | 字段合同应分别包含来源列、期间语义、单位及核验状态；沿用现有[逐列语义核查](fina-indicator-dsl-descriptions.json)。不得由 `roe` 猜 TTM，由 `gross_margin` 猜毛利率，或由 `assets_yoy` 猜同比。 |

单位核验应使用具有相同证券、报告期、公告版本和口径的来源对照；单个正常值的数量级不能成为全部金额/比例字段的单位证据。换算常数与定义应版本化，未知单位不能参与隐式换算。若产品要求 223 个字段全部具备可组合的规范单位，逐列单位验收就是发布条件；“来源原值可查询”与“规范单位已核实”是不同状态。

新版对外可以承诺 **223 个明确登记的研究字段，以及可核查的来源、版本和覆盖信息**。不能仅以字段数、请求成功或日期跨度承诺 223 列全历史无缺失、全部行业适用或完整 PIT；研究准入应使用实际覆盖和语义状态判定。
