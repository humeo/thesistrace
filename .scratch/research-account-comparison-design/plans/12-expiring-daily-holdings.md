## Contract and scope

Ticket 12 and parent spec section 9 are authoritative. Ticket 11 was independently accepted and committed as c9a7c86e; work starts from that clean isolated checkout. Implement only the current contract, without compatibility aliases, migrations or historical-engine support. No dev/production data changes. Ticket 13 reruns and ticket 14 final acceptance remain untouched.

Normal Strategy Run, each Batch child Run, and each successful Track Advance publish an independent immutable diagnostic unit. It contains actual positions at the Open reporting point after execution and costs, plus explicit Session coverage for legitimate all-cash dates. Expiry is successful publication/last successful detail read plus seven days. Summaries, metadata, polling and Refresh do not renew other units. Expired data is unavailable before physical deletion finishes. Permanent Result, checkpoint, settlement evidence and continuation must work independently.

## Existing seams and intended implementation

- Kernel: collect positions through a bounded observer at the existing post-execution valuation point. Do not enable the full diagnostic ledger or retain histories in terminal state. Research Chunk and Track segments own collected rows; Factor supplies none. Compare observer on/off using the same public execution inputs.
- Publication: compressed partition payloads and small metadata live separately from permanent Result. Existing execution checkpoints may protect staged fragments until success/retry; final success binds the temporary publication and releases execution staging normally. Preserve current fence/atomic-success semantics across Run, Batch and Track.
- Lifecycle: introduce one Daily Holding retention owner with source/Researcher, immutable publication reference, coverage, successful publication/read timestamps and expiry. Server database time determines expiry. Detail reads and expiry share a lock order; an admitted read verifies bounded content before renewal commits, failed reads roll back. Expiry first revokes access/reference; existing Publication release and queued deletion perform reference rechecks and retry physical failures. No bucket-age deletion and no new service or permanent market-data pin.
- Access: typed date/instrument queries, maximum50 rows, opaque source-bound cursor, coverage/status and expires_at. Existing Run/Track ownership and MCP scopes gate reads and renewal. Separate availability reads from explicit detail requests; distinguish available empty coverage, expired and not_recorded. Track pagination remains bound to its source units when newer segments arrive.
- UI: on-demand daily holdings panel alongside event evidence, explicit loading and next-page actions, validity/status and source display. No summary prefetch; no automatic rerun. Existing current contract discovery states the successful-read retention side effect.
- Maintenance: integrate bounded expiry work with the existing maintenance lifecycle and reuse Publication object deletion/reference protection. Protect cancellation/unpublished staging through existing ownership boundaries.
