# 06 — 每日 Factor 证据与月年统计：实施计划

Status: in-progress

基线：05 `0fbcaae` 已独立提交，沿用同一隔离 worktree。只实现当前合同；没有迁移、旧产物适配或版本分支。06 完成验收、串行 Standards/Spec 审查和独立提交前不开始 07。

## 已定位的行为与缺口

- `research_kernel/factor.py` 已计算 1/5/20 Session 的每日 IC、Rank IC、五组收益与 Top-Bottom；30 个样本下相关性/分组不可定义，平均排名处理 ties，不拆并列。
- 行式 `build_forward_labels` 已记录逐样本标签排除及末日右删失；列式 `PreparedColumnarForwardLabels` 目前将多种 unavailable 合并为状态 1，每日投影丢失排除原因、组人数和覆盖分母。需要在共享每日证据合同中对齐，而不是持久化全股票 Alpha/Label 矩阵。
- `research_chunks.py` 按期限等待标签成熟，最终 Chunk 解决尾部；`advance_factor_state_from_daily` 只累加全期摘要，未向 Worker/Batch 交付每日证据。普通 Result 当前仅保存 `factor_summary`，不能从它恢复每日值。
- 既有 Run/Batch 的分区发布、Checkpoint 复用和拥有者绑定分页可用于新增证据；05 common 产物不是 Factor 每日证据，不混合两个定义。Track/Strategy 不计算 Factor。

## 交付步骤

1. 补小样本回归，固定每日证据：信号日期、期限、标签入口/出口与可评价状态、Final Alpha/有效样本数、Alpha 与标签排除/覆盖分母、五组人数/收益、IC/Rank IC 和不可定义原因。测试同序/反序的 ±1、ties/空组/小样本，以及末日右删失。
2. 统一行式/列式每日投影，保留真实原因；严格限定 t+1 到 t+1+h Open 在请求研究末日内，即使 Data Generation 有更晚历史也不取。成熟期跨月不重新截断。
3. 从 Chunk 产出已解析的每日观察，普通 Factor Run 与 Factor Batch 分区保存并发布；检查冻结期限/日期覆盖、唯一顺序、内容摘要和重试复用。摘要与每日证据来自同一计算，不写全股票矩阵；Strategy/Track 保持无 Factor 执行。
4. 用现有确定性统计语义按信号日期归并全期、月、年统计，IC/Rank IC 等日权，ICIR 样本标准差。返回实际可评价日期范围、数量和尾部右删失数量；不增加含义不明的稳定性评分。
5. 增加类型化 Factor 每日/时段结果 sections：期限和信号日期过滤、最多 50 条、Result/过滤/Researcher 绑定 cursor。缺失必须有的产物报不可用，不伪造空记录；保持读取有界。
6. 同步 HTTP、原生 MCP 和 Factor 结果视图，默认摘要、按需分页每日/时段数据，注明五组和 Top-Bottom 是未扣费标签统计；页面不下载全矩阵过滤。
7. 验证独立人工计算、Chunk/全量一致性与尾部、真实普通/Batch 发布及恢复、分页授权/游标、浏览器统计交互和 MCP。按实际影响选择现有检查，保留首次失败与修复证据。Standards → Spec 串行审查，修复复审后更新 tracker 并独立提交。
