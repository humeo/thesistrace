## 阻塞关系的理由

- 当前可启动的是 01、02、04、06；它们不因为同属一个功能或可能编辑同一文件就互相阻塞。
- 03 使用 01 已去除 Factor 依赖的策略终态，集中修改末日与连续追踪合同。
- 07 需要实际本金（02）、完整终态（03）及共享表达式编译（04），先交付固定仓位和独立选股周期；08 再接入共同序列（05）实现日频条件仓位。07 和 08 都是完整可演示功能，不先摆出不可运行的前端选项。
- 09 与 10 共用 07 的相对权重/保留目标合同，各自实现一种配权，不人为要求排名先于逆波动。
- 11 消费 08 已完整定义的目标模式和执行结果；它不依赖某一种非等权算法。
- 12 只需 03 的完成观察与发布边界，就能存储并安全过期每日持仓，不等待共同指标、配权或永久交易明细。
- 13 使用 12 的过期状态和 02 的实际本金/模拟条件，创建有来源的新 Run；不是精确重放，也不是原 Attempt Retry。
- 14 的直接阻塞为 06、09、10、11、13，它们传递覆盖其余任务；不重复列所有祖先，也不借整体验收延后各票本应完成的功能。

## 历史交付约束（涉及迁移的内容已被上述最新决定替代）

已有在线产品及永久 Result，采用保留数据的协调直接切换。应用只执行当前合同，不因本地开发而假定可清库，也不为票间过渡引入新旧运行时并存。

正式实现按 main 基准在需要的隔离工作区推进；先验证隔离，不自动修改或提交原目录。涉及持久输入、Result、Checkpoint 或产物定义的票随行为交付明确起止版本、备份、执行记录、失败回滚及重复执行证据；没有实际持久变化的票不为保持中间状态而虚构迁移。

每票包含对应的 Core、HTTP/MCP、网页及必要验证。与该行为无关的页面无需机械修改；公开接口测试可以证明不需要 UI 变化的恢复/存储语义。01 本身就是可用行为，不另开一个横向框架准备票；必要内部重构在消费它的最早功能票内先完成，不交付无人使用的抽象。

业务无阻塞不代表可以安全同时写同一批文件；实际执行应检查共享契约改动并安排集成。中间未接通的分支不得作为已完成切片发布，所有集成先进入 main，部署分支只接收 main 的更新。本次仅发布已确认任务，尚未执行实现、迁移或部署。

每票先跑受影响验证、关闭审查问题并独立提交；14 在联合版本做规定的整体验收与迁移演练，依实际改动边界选择必要镜像证据。保留当前 dev 的容器数据、数据卷和 Dataset Head；不重复复制仓库测试 runbook。
