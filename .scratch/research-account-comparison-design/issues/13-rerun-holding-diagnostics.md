# 13 — 过期后用当前数据重新回测

**What to build:** 每日持仓过期后，Researcher 或 Agent 可显式创建使用当前数据的新回测继续排障，新结果关联原研究但不覆盖它。

**Blocked by:** 02 — 按实际本金回测并延续同一账户；12 — 临时保存每日持仓，读取续期并安全清理

**Status:** complete

- [x] 网页过期视图提供明确重新回测操作；Agent 使用既有提交能力，读取过期状态本身不提交任务，不因数据版本不同再加额外确认。
- [x] 新普通 Strategy Run 复用原策略、实际本金/模拟参数及研究区间，在当前合同/当前 Data Generation 正常准入、排队、预算和取消；使用新 request_id，不是原 Attempt Retry。
- [x] 记录 source_run_id 及必要 Track/Checkpoint 来源与新旧数据/规则身份；新结果属于新 Run，页面和 MCP 标明当前数据重新回测并可返回原研究。
- [x] 旧 Generation 或旧引擎不可用仍可重跑；人为修订历史价格导致新旧收益不同也能成功，不设置相等门槛、不调整策略凑旧收益。
- [x] 旧输入在当前合同下非法时给出正常定位诊断，不加旧版本执行器、字段别名或隐式参数替换；单次新 Run 仍冻结一致数据。
- [x] Track 历史排障从其对应原始研究起点算至调查日期，不能从中间日全现金冒充连续历史；使用 Track 自有 Origin 支持源 Run 已删除，不覆写 Track 发布历史。
- [x] 新持仓不填回旧产物，原 Result/Track/cursor 不改变；新 Run 按既有临时持仓规则保留和续期。
- [x] 真实依赖与一条网页/MCP 闭环验证数据修订、旧数据不可用、请求幂等、所有权、取消及来源关联；来源元数据采用当前合同。
