# Configuration management

Runtime configuration has one explicit file per deployment. Development reads
the private repository-root `.env`; `THESISTRACE_ENV_FILE` explicitly selects a
different file. Production requires that same variable to name an absolute file
outside the checkout, owned by root with mode `0600`. Lifecycle commands clear
ambient Compose variables so a terminal's old credentials cannot override the
selected file. They never execute the file as shell code.

## Maintained sources

| Source | Owns | Contains secrets? |
| --- | --- | --- |
| `tooling/config/fields.mjs` | Deployment input definitions, types, defaults, required conditions and sensitive markers | No |
| `.env.example` | Generated by `pnpm config:template` from those definitions | No; credential fields are empty |
| `.env` or explicit `THESISTRACE_ENV_FILE` | One deployment's settings and credentials | Yes; private, mode `0600`, excluded from Git and Docker builds |
| `apps/agent/config/model-registry.json` | Model identity, context/output capacities, compression minimum, reasoning choices, provider credential variable names | No |
| `deploy/compose.yaml` and environment overlays | Service graph, internal addresses, mounts, resource limits and credential delivery | No live credentials |
| `.mise.toml`, lockfiles and Dockerfiles | Toolchain and dependency versions | No |
| `tooling/test/runtime`, `apps/auth/compose.test.yaml`, `apps/agent/compose.test.yaml` | Isolated test identities, fixed fixtures and fake services | Disposable test credentials only |
| `apps/auth/src/config.ts`, `apps/agent/src/config.ts`, Core settings | Service-owned runtime validation | Read process environment; no independent dotenv loading |

Keep internal service addresses and invariant contracts in Compose/code. Add an
environment setting only when a deployment actually needs to choose the value.
Models are edited in the registry, not duplicated in env files. The frontend
receives the validated public model catalog; provider secrets stay on Agent.

## Development setup

```sh
mise exec -- pnpm config:init
# Edit .env without committing it.
mise exec -- pnpm config:check
mise exec -- pnpm dev:up
```

Initialization generates independent database passwords, object-store keys,
the Auth secret, an Ed25519 MCP key pair, and a Development account password. It creates the file with `0600`
permissions and refuses to overwrite existing configuration. External service
credentials and the verified mail sender must be filled by the Operator.
Do not regenerate passwords for an existing database by deleting its env file;
the stored database role passwords and configured passwords must match.

`config:check` validates the literal file and required settings, then renders
Compose with `config --quiet`. It does not contact Tushare or model providers,
start services, change data, or print credentials. Missing or placeholder
Tushare credentials fail before any container is started. Service-specific
validation still runs when each service starts.

Files use one unquoted `NAME=value` per line. Blank lines and comment lines are
allowed. Values may contain JSON or email display names, but no variable
expansion, `$` or `#` characters, outer quotes, inline comments, duplicate names
or unknown settings. This avoids differing comment/interpolation behavior
between Node and Compose.
Private `.env` files and `*.env` files are excluded from Git and Docker contexts.

For a private host CLI or an explicitly authorized live evaluation:

```sh
mise exec -- pnpm config:run <command> <arguments>
mise exec -- pnpm check:live-tushare
```

`config:run` loads the same file without shell expansion. Ordinary deterministic
test commands never load it; their Compose invocations explicitly use
`--env-file /dev/null` and inject only their isolated test configuration.
Do not run deterministic checks through `config:run`.

`THESISTRACE_PUBLIC_ORIGIN` is the single browser origin. For example,
`http://127.0.0.1:5180` derives port 5180, the issuer `/api/auth`, the resource
`/mcp`, and the allowed host/origin lists. Do not put `THESISTRACE_DEV_WEB_PORT`,
`THESISTRACE_MCP_ISSUER_URL`, `THESISTRACE_MCP_RESOURCE_URL`,
`THESISTRACE_MCP_ALLOWED_HOSTS` or `THESISTRACE_MCP_ALLOWED_ORIGINS` in the file.

Every launch injects the resolved values with `--env-file /dev/null`; Compose
does not parse the private file a second time. Worker settings for RESEARCH,
BATCH_RESEARCH and TRACKING include `CPU_COUNT`, `MEMORY_BYTES`,
`EXECUTION_MEMORY_BYTES` and `CALCULATION_THREADS`. Threads cannot exceed CPUs;
execution memory cannot exceed three quarters of the container budget.

## Runtime variables

| Group | Variables | Consumer |
| --- | --- | --- |
| Deployment | `THESISTRACE_ENVIRONMENT`, `THESISTRACE_PUBLIC_ORIGIN` | Auth, Agent, Core, Caddy |
| Published Development ports | `THESISTRACE_DEV_POSTGRES_PORT`, `THESISTRACE_DEV_S3_PORT`, `THESISTRACE_DEV_S3_CONSOLE_PORT`, `THESISTRACE_DEV_API_PORT` | Development Compose only |
| Database credentials | `THESISTRACE_OWNER_DATABASE_PASSWORD`, `THESISTRACE_CORE_DATABASE_PASSWORD`, `THESISTRACE_AUTH_DATABASE_PASSWORD`, `THESISTRACE_AGENT_DATABASE_PASSWORD` | PostgreSQL and corresponding role only; Compose derives database URLs |
| Object store | `THESISTRACE_S3_ACCESS_KEY_ID`, `THESISTRACE_S3_SECRET_ACCESS_KEY` | RustFS and Core services using its store |
| Development account | `THESISTRACE_DEV_RESEARCHER_EMAIL`, `THESISTRACE_DEV_RESEARCHER_NAME`, `THESISTRACE_DEV_RESEARCHER_PASSWORD` | Development Auth initializer only; creates an absent identity without changing existing credentials |
| Authentication | `BETTER_AUTH_SECRET` | Auth only |
| Mail | `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, `THESISTRACE_RESEND_API_URL` | Auth only |
| Market/Financial/Industry source | `THESISTRACE_TUSHARE_TOKEN` | Data Operator Worker only |
| Model providers | `THESISTRACE_AGENT_OPENAI_API_KEY`, `THESISTRACE_AGENT_ANTHROPIC_API_KEY`, `THESISTRACE_AGENT_GOOGLE_API_KEY`, `THESISTRACE_AGENT_OPENAI_BASE_URL` | Agent only; enabled registry entries require their named credential |
| Image identity | `THESISTRACE_AUTH_IMAGE`, `THESISTRACE_AGENT_IMAGE`, `THESISTRACE_AGENT_BUILD_REVISION` | Compose and Agent diagnostics |
| Execution budgets | `THESISTRACE_RESEARCH_WORKER_EXECUTION_MEMORY_BYTES`, `THESISTRACE_TRACKING_WORKER_EXECUTION_MEMORY_BYTES`, `THESISTRACE_AGENT_RUN_MAX_WALL_SECONDS` | Corresponding Workers/Agent |
| MCP identity | `THESISTRACE_MCP_CLIENT_ID` | Auth/Core |
| MCP signing | `THESISTRACE_MCP_SIGNING_PRIVATE_JWK`, `THESISTRACE_MCP_VERIFYING_PUBLIC_JWK` | Private key only to Auth; public key to verification consumers |
| MCP policy | `THESISTRACE_MCP_AGENT_SCOPES`, `THESISTRACE_MCP_DEPLOYMENT_TOOLS` | Auth/Core |
| MCP timing | `THESISTRACE_MCP_ACCESS_TOKEN_TTL_SECONDS`, `THESISTRACE_MCP_CLOCK_SKEW_SECONDS` | Auth/Agent/Core |

`CLI_API_KEY` and `TUSHARE_TOKEN` are not application configuration names.
The model registry JSON is transported as `THESISTRACE_AGENT_MODEL_REGISTRY`
by the launchers; it is not accepted as an inline local setting. Internal URLs,
data mounts and bucket identity are derived by Compose, not copied into `.env`.
Test-only variables are owned by their test runners and never belong in a live
deployment file. See the lifecycle and evaluation runbooks for test selectors.

## Internal and test configuration

These settings exist at process boundaries but are not deployment-file inputs:

| Settings | Maintained by |
| --- | --- |
| `THESISTRACE_DATABASE_URL`, `THESISTRACE_OWNER_DATABASE_URL`, `THESISTRACE_AUTH_DATABASE_URL`, `THESISTRACE_AGENT_DATABASE_URL` | Compose derives URLs from the deployment's four role passwords |
| `THESISTRACE_AUTH_INTERNAL_ORIGIN`, `THESISTRACE_INTERNAL_API_ORIGIN`, `THESISTRACE_MCP_INTERNAL_URL` | Compose service routing |
| `THESISTRACE_AUTH_HOST`/`PORT`, `THESISTRACE_AGENT_HOST`/`PORT` | Fixed container listeners and isolated test runners; published Development ports are configured separately |
| `THESISTRACE_S3_ENDPOINT_URL`, `THESISTRACE_S3_BUCKET`, `THESISTRACE_S3_REGION`, `THESISTRACE_DATA_MOUNT`, `THESISTRACE_BENCHMARK_MOUNT`, `THESISTRACE_BATCH_ATTEMPT_CONTROL_DIRECTORY` | Compose storage contract |
| `OPENAI_BASE_URL` | Compose maps the canonical `THESISTRACE_AGENT_OPENAI_BASE_URL` to the SDK variable inside Agent |
| `THESISTRACE_TUSHARE_ENDPOINT` | Isolated source-server tests; normal Workers use the official endpoint |
| `THESISTRACE_TEST_*`, `THESISTRACE_AUTH_TEST_*`, `THESISTRACE_AGENT_TEST_*`, `THESISTRACE_QUALIFICATION_*`, Scripted-model secrets | Test/evaluation runners and fixtures |
| Mounts, health probes and logging limits | Compose topology |

The Web application has no private dotenv loader or browser credential variables.
Its build and routing configuration remain in `apps/web/vite.config.ts`, the Caddy
configuration, and the maintained frontend source. Do not add secrets to a Web
build setting.

## Applying changes

Edit the private file and run `pnpm config:check`, then `pnpm dev:up` to recreate
services with changed configuration. Restart alone does not replace container
environment variables. Changing a provider token does not refresh Canonical
Data; submit the intended Data Refresh after Worker health recovers.

Production uses `THESISTRACE_ENV_FILE=/etc/thesistrace/production.env
pnpm prod validate` and `up` as documented in the
[Production runbook](single-node-production.md). Its validator rejects weak,
placeholder and Development values and protects the external file permissions.
Production operations use the same Node 24 configuration loader.
`dev:stop`, `dev:status`, `dev:logs`, and `prod down/status/logs` select existing
resources by exact Compose project labels and do not read the configuration file.
Stopping/removing containers retains data volumes.

This follows Docker Compose's [explicit env-file loading and interpolation
rules](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/),
with an application rule that the selected file is authoritative.

The model registry requires `max_output_tokens` independently from `context_window`.
`min_compaction_context_window` controls whether a selection can compress; it is
not the normal trigger. See [Session context and recovery](session-context.md)
for the exact budgets, 90% trigger and model-switch behavior.
