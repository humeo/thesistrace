# Expose one capability-gated Operator Console without general RBAC

Exactly one authenticated Researcher holds the indivisible Operator Capability through an Auth-owned singleton Operator Assignment and may use the same-origin `/operator` Console, or private operational commands, to review Researchers and Invitations, issue or reissue Invitations, revoke another Researcher's Login Sessions, submit Market, Financial, and Industry Refreshes separately with the same explicit target inputs as their CLI contracts, and inspect Dataset Operational Status. Initial assignment and atomic transfer remain private deployment commands, transfer revokes the former Operator's Login Sessions, and the Console cannot target its own Operator for Session revocation. Ordinary Researchers receive `404` and no navigation affordance, while every Console mutation requires an Auth-issued, single-use current-password Operator Proof bound to that exact request. This replaces the private-command-only and no-Web-administration scope without installing the Better Auth Admin plugin or introducing a separate administrator identity, generic roles or RBAC, Organizations, Researcher deactivation or deletion, impersonation, administrator-set credentials, an ambiguous combined Refresh, a new unified Operator audit surface, or raw-storage browsing.
