## 优先问题

### 1. [P1] 每日跟踪丢失研究名称，三条记录难以辨认

实见三条跟踪的主要标签均为 `track_*`，日期和状态相同，来源仅为 `run_*` 文本；详情标题仍是通用“每日跟踪”。用户必须记住 ID 或逐条打开才能辨认策略，容易查看或管理错对象。

建议：以来源研究名称或明确的策略标签作为列表和详情主标题，技术 ID 降为可复制的次要信息；提供具名来源运行链接。保持资源 ID 契约不变，若接口缺少名称，应补充真实名称读取，不能臆造。

位置：[DailyTracksPage.tsx:338](/Users/koltenluca/code-github/thesistrace/apps/web/src/daily-tracks/DailyTracksPage.tsx:338)、[DailyTrackWorkspace.tsx:43](/Users/koltenluca/code-github/thesistrace/apps/web/src/daily-tracks/DailyTrackWorkspace.tsx:43)。对应命令：`$impeccable clarify`。

### 2. [P1] 研究失败后，解释和恢复入口不足

实见“UI验收·Direct”失败运行仅显示“研究执行失败。”，首屏操作是返回和删除；“创建草稿”排在配置、进度和组织信息之后。用户等待 3 分 47 秒后，无法判断应该改代码、稍后重试，还是联系维护者。

建议：在失败提示旁给出安全的原因分类、明确下一步和“使用本次配置创建草稿”。未知原因应明确说明诊断不可用，并保留可供定位的运行标识。继续保护内部敏感信息，不直接展示原始异常。当前证据不能推断该运行实际失败原因，也不说明所有错误都缺少诊断。

位置：[ResearchRunsPage.tsx:295](/Users/koltenluca/code-github/thesistrace/apps/web/src/research-runs/ResearchRunsPage.tsx:295)、[ResearchRunsPage.tsx:338](/Users/koltenluca/code-github/thesistrace/apps/web/src/research-runs/ResearchRunsPage.tsx:338)、[errors.ts:56](/Users/koltenluca/code-github/thesistrace/apps/web/src/research-runs/errors.ts:56)。对应命令：`$impeccable harden` / `clarify`。

### 3. [P2] Research 编辑时，检查/运行按钮不在视野内

三种编辑模式在约 720px 高桌面首屏均看不到检查和运行按钮。页面末尾虽然声明 sticky，专用样式又将其覆盖为 `position: static`。反复修改、检查时需要长距离滚动，打断反馈循环。

建议：提供不遮挡内容的持续可达操作区，包含检查、运行和草稿状态；减少编辑器上方冗余空间。该问题位于当前已批准的 Research 改造范围内。

位置：[ResearchWorkspacePage.tsx:795](/Users/koltenluca/code-github/thesistrace/apps/web/src/research/ResearchWorkspacePage.tsx:795)、[research-perplexity.css:209](/Users/koltenluca/code-github/thesistrace/apps/web/src/research/research-perplexity.css:209)。对应命令：`$impeccable layout`。

### 4. [P2] 空仓位被摘要描述为“由公式决定”

实见草稿选择“固定比例”，输入为空，摘要却显示“股票仓位 由公式决定”。源码将所有无法解析成固定百分比的值统一映射为动态仓位，包含空字符串。

建议：分别表达未设置、有效固定比例、有效公式和无效输入；未填写时明确标示待完成，不默认推断交易规则。当前发现是摘要不准确，未证明后端接受了无效配置。

位置：[StrategyRuleSummary.tsx:19](/Users/koltenluca/code-github/thesistrace/apps/web/src/research/StrategyRuleSummary.tsx:19)、[ResearchPositionSizing.tsx:21](/Users/koltenluca/code-github/thesistrace/apps/web/src/research/ResearchPositionSizing.tsx:21)。对应命令：`$impeccable clarify` / `harden`。

### 5. [P2] 管理表格为完整 UUID 让出过多操作空间

在 1280px 桌面中，研究员表格内部宽 1187px、可见区域 977px，仅一条记录也需横向滚动；当前会话、邀请和操作列被挤到右侧。它没有造成整页溢出，但增加了核对身份和执行会话管理的成本。

建议：优先保留姓名/邮箱、访问状态、会话数量和操作；完整 ID 放入可复制的次要详情，确保身份与关键操作同时可见。

## 认知负担与情绪路径

单一焦点、视觉层级和逐步决策在 Research 长表单中部分受影响；信息分块、相关内容分组和渐进披露总体较好。最明确的工作记忆负担出现在 Daily Tracks 的跨页 ID 对照。五个结果标签或六项指标本身不构成过载；管理表格八列同时争夺可见宽度才有实际证据支持。

| 检查项 | 结论 |
|---|---|
| 单一焦点 | 部分满足：编辑与检查操作距离远 |
| 信息分块 | 基本满足：框架按研究问题组织 |
| 相关内容分组 | 满足：字段详情、参数和证据有明确分组 |
| 视觉层级 | 部分满足：失败后的删除比恢复更显眼 |
| 一次一个决策 | 部分满足：长配置与摘要需往返核对 |
| 可见选择数量 | 需按任务判断：管理表格列数已产生实际横向负担 |
| 工作记忆 | 不满足：跟踪与来源依赖记住 ID |
| 渐进披露 | 满足：可选参数和证据详情分层展开 |

情绪路径：首页带来好奇 → 框架问题帮助起步 → 隐藏的运行入口增加迟疑 → 成功图表形成证据反馈 → 泛化失败提示造成明显低谷 → 再次查看跟踪时，缺少具名策略削弱连续性。
